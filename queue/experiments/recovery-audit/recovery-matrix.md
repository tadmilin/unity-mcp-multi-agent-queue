# Recovery: why, when, how, and time boundaries

Audited workspace: `C:/Users/User/Desktop/unity-mcp-multi-agent-queue`. Paths below are relative to this repository. `W/` means `queue/UnityProject/Tools/UnityWorkflowMcp/`; `C/` means `queue/UnityProject/Tools/UnityJobCoordinator/`; `N/` means `queue/UnityProject/Tools/UnityNativeObserver/`.

Recovery exists because losing a response does not prove that Unity failed to execute a command. Replaying a write, import, Play, or Stop can duplicate a mutation or interfere with another owner. The runner first tries to establish the outcome of the original operation. If it cannot, it retains quarantine. Separate cleanup routes can restore safe queue availability while leaving the original task unsuccessful.

## Availability improvement and bounded validation

Initial checkout used v2 and intentionally failed closed on unavailable confirmation. Historical q02 used v3. A new deterministic test arranged completed import plus one unavailable response and a newly published registration before the wait slept: v2 raised `Import confirmation unavailable; no polling or replay`. Root approved copying historical import_wait.py **byte-for-byte**; source SHA-256 `7293ce2d8b9c7cc51aca471a46113febab5ec554743852a68cb02633111f6c49`.

The port improves availability for that already-observed read-only reconnect case. It introduces no mutation replay, extends no deadline, and changes no receipt/ownership checks. Four new tests cover successful reconfirmation; disk owner/receipt/native epoch changes; live receipt mismatch; expired original deadline. Existing unchanged-generation test still performs one RPC. All 86 import/recovery tests pass. `server.py:22` and `server.py:37` export the module VERSION and load hash dynamically. No additional runtime dependency changed; native registration already emits connected_unix.

Classification nuance: `confirm()` classifies **any returned non-dictionary or non-success status** as unavailable, including authority denial such as `EDITOR_QUEUE_TOKEN_INVALID`; it does not restrict that classification to transport errors. Thrown exceptions propagate. An authority denial may therefore cause an extra read-only attempt on a new registration event or waiting until the original deadline. It cannot authorize mutation or acceptance: each loop rechecks disk secret hash/owner/ticket/receipt/lease/native identity, and acceptance still requires a successful matching live confirmation. This is an availability/diagnostic distinction, not a bypass of the authority checks (`MCPForUnity/Editor/Tools/EditorQueueState.cs:104`, `:200`).

Slide wording: **“Recover evidence first; never replay an uncertain mutation. Cleanup recovery frees a proven-safe queue but does not turn a failed task into success. Reconnect confirmation was observed in 1.575–2.837 seconds in eight historical cases; this is not an SLA.”**

## New isolated Play qualification: ACK recovery extension

Actual isolated Preview job `60090f568c6248b0b84f3cfc917d4e5f` returned successful start-play execution, then its ACK returned a disconnected-session failure. Six status-unavailable events preceded the recovered status showing the same ticket/operation still **complete**, not acknowledged. The original worker quarantined with `Acknowledgement unavailable; inspect receipt`. This is a failed live qualification, not autonomous recovery success. Root owns all live reconciliation; this helper performed read-only inspection only.

Old execute_code also sets Play synchronously and returns; it has no ACK-before-reload barrier. This evidence does not prove the new helper caused the race. An isolated mock of the real PhaseWorker reproduced the exact availability failure with one start execution and one failed ACK before dispatch. Root approved the narrow ACK reconciliation policy above. The helper clamps status and supplemental ACK RPC budgets to the same remaining deadline; successful late status is rejected. All ownership/receipt/PID/result/hash checks are required before the one supplemental ACK. Runtime scope is only `phase.py`; test changes only `test_phase.py`. Root subsequently validated one natural ACK disconnect in the isolated Editor: the fixed job completed, restored the scene and released the gate with exactly one start-Play, one stop-Play and one supplemental ACK. Failed-ACK response to confirmed acknowledgement was 10.370692 seconds. The earlier failed job was separately operator-cleaned and resolved as abandoned; it was not retroactively counted as successful. The successful job had waited behind that quarantine and its terminal result was recovered by the same submission key after its client observation timed out.
